你现在需要从零开发一个 **AI4Math Research Progress Tracker** 网站。

## 一、项目目标

开发一个面向 AI4Math（AI for Mathematics）领域的研究进展追踪平台。

网站的核心目标不是简单展示论文，而是帮助研究人员快速回答：

1. 最近 AI4Math 领域发生了什么重要进展？
2. 哪些研究方向最近比较活跃？
3. 某一项研究进展具体解决了什么问题？
4. 它与之前哪些工作有关？
5. 论文、代码、模型、Benchmark、数据集之间有什么关系？

第一版先做成一个 **可运行、可交互的 MVP**，重点是把网站整体框架和核心数据流跑通。

不要为了追求功能数量而把项目复杂化。

---

# 二、总体技术方案

推荐使用：

- Frontend：Next.js + React + TypeScript
- UI：Tailwind CSS
- Backend：优先使用 Next.js API Routes / Route Handlers
- Database：PostgreSQL
- ORM：Prisma
- AI：预留 LLM API 接口
- Deployment：结构上兼容 Vercel
- Package manager：npm 或 pnpm

如果当前环境已经存在成熟的项目模板或技术约束，可以合理调整，但必须保持：

> 前端 → API → 数据层 → Research Event

这条主线清晰。

# 六、Research Event 和 Paper 必须区分

例如：

一篇论文可能只是普通论文。

而 Research Event 是：

> 一项真正值得关注的研究进展。

所以应该允许：

```text
ResearchEvent
      │
      ├── Paper
      ├── GitHub
      ├── Model
      ├── Benchmark
      ├── Dataset
      └── Related Works
```

一个 Event 可以对应多篇论文。

一篇论文也可能参与多个 Event。

因此数据库结构尽量考虑未来的多对多关系。

# 十二、AI Agent 接口

第一版必须给未来 Agent 留出清晰接口，但不要为了 MVP 实现一个复杂的 Multi-Agent System。

建立类似：

```text
src/
  agents/
    researchTracker/
      tracker.ts
      classifier.ts
      summarizer.ts
```

或者合理的等价结构。

Agent 的职责未来包括：

```text
1. 获取新论文
2. 获取 GitHub 项目
3. 判断是否属于 AI4Math
4. 判断 Research Area
5. 判断是否构成真正的 Research Progress
6. 提取 Research Event
7. 判断重要程度
8. 生成摘要
9. 提取 Paper / Code / Model / Benchmark
10. 查找 Related Works
```

第一版可以只实现：

```text
Raw Research Item
       ↓
AI4Math Classifier
       ↓
Research Event
```

并且使用 mock data / mock LLM provider，让网站不依赖真实 API 也可以运行。

# 二十一、最重要的产品原则

整个项目不要做成：

> “一个 AI 帮你总结论文的网站”。

而应该做成：

> **“一个帮助研究人员理解 AI4Math 研究进展的 Research Intelligence Platform。”**

因此所有页面都应该围绕：

```text
What happened?
Why does it matter?
What problem does it address?
What did it improve?
What came before it?
What came after it?
Where can I read the original work?
```

这些问题设计。
